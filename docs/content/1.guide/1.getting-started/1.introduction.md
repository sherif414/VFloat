## What is VFloat?

VFloat is a headless engine built on Vue 3.5 reactivity for positioning and coordinating anchored floating elements, such as tooltips, popovers, dropdown menus, context menus, and dialogs.

Instead of monolithic components that lock you into rigid HTML or opinions on design, VFloat provides composable building blocks for positioning geometry, user interactions, and focus management. You write the template and the CSS. VFloat handles the physics.

## Why floating elements are hard

Every floating element, from a tiny tooltip to a nested dropdown menu, looks simple until you actually build one.

A button needs a tooltip. You measure the button, set absolute positioning, and show it on hover. Then the button moves near the edge of the screen and the tooltip clips offscreen. You fix that, but moving the cursor across the gap causes the tooltip to flicker closed. You fix the gap, but the user presses Escape or scrolls the container, and the floating box stays stuck in place.

None of these problems are complicated on their own, but solving geometry, event timing, outside clicks, and keyboard focus for every component in your application quickly turns into hundreds of lines of fragile glue code.

## Headless by design

Prebuilt component libraries solve this by packaging everything into finished widgets like `<Tooltip>` or `<Menu>`. That works well until you need custom markup, a unique DOM structure, or styles that do not fit the library's design tokens.

VFloat takes the headless approach. It does not provide HTML tags, pre-styled widgets, or opinions on how your interface should look. Instead, it provides the underlying reactive machinery: positioning math, viewport collision detection, event listeners, and focus coordination.

## The three core layers

Every floating surface in VFloat is divided into three focused responsibilities:

- **The Hub** ([`useFloatingNode`](/api/core/use-floating-node)) manages element references (`anchorEl` and `floatingEl`) and tracks reactive open state. It acts as the coordinator between positioning and interaction without coupling them directly.
- **The Positioning Engine** ([`usePosition`](/api/positioning/use-position)) solves **where** the floating element sits. It tracks scrolling and resizing, runs middleware (such as `offset`, `flip`, and `shift`), and applies inline coordinates to your floating element automatically.
- **The Interaction Layer** ([`useHover`](/api/interactions/use-hover), [`useClick`](/api/interactions/use-click), [`useEscapeKey`](/api/interactions/use-escape-key), [`useOutsideClick`](/api/interactions/use-outside-click)) solves **when** the surface appears or disappears. It listens for user gestures and toggles `node.open`.

Here is how those three pieces fit together in a complete tooltip component:

```vue
<script setup lang="ts">
import { ref } from "vue";
import { useEscapeKey, useFloatingNode, useHover, usePosition } from "v-float";

const anchorEl = ref<HTMLElement | null>(null);
const floatingEl = ref<HTMLElement | null>(null);

// 1. The Hub: holds state and element references
const node = useFloatingNode({ anchorEl, floatingEl });

// 2. Where: calculates coordinates and auto-applies styles
usePosition(node, {
  placement: "top",
  middlewares: { offset: 8 },
});

// 3. When: manages open state from user gestures
useHover(node);
useEscapeKey(node);
</script>

<template>
  <button ref="anchorEl" type="button">Hover me</button>

  <div v-if="node.open.value" ref="floatingEl" role="tooltip">
    Tooltip content
  </div>
</template>
```

Notice how clean the template stays. By default, `usePosition` updates the floating element's styles directly as coordinates change, so you do not need manual `:style` bindings.

When the user hovers over the button, `useHover` sets `node.open` to `true`. Vue mounts the tooltip into the DOM, and `usePosition` calculates coordinates and positions it above the anchor. When the cursor leaves or the user presses Escape, the interaction composables set `open` back to `false`, and Vue unmounts the element.

Neither side needs to know about the other: `usePosition` never attaches mouse listeners, and `useHover` never calculates pixel math.

## Composing different surfaces

Because VFloat provides independent composables rather than rigid components, you never have to learn a new paradigm for a different pattern. You build any floating interface by swapping or combining behaviors on the same node.

To turn the tooltip into a popover, replace hover with click and outside-click dismissal:

```ts
useClick(node);
useOutsideClick(node);
useEscapeKey(node);
```

To turn that popover into a keyboard-navigable dropdown menu, add roving focus:

```ts
const itemEls = shallowRef<(HTMLElement | null)[]>([]);

useClick(node);
useOutsideClick(node);
useEscapeKey(node);
useRovingFocus(node, { elementsList: itemEls });
```

To build an accessible modal dialog, keep the click trigger and add focus containment:

```ts
useClick(node);
useFocusTrap(node, { modal: true });
useOutsideClick(node);
useEscapeKey(node);
```

The template and styling remain completely yours. You only assemble the behaviors your surface actually needs.

## Relationship to Floating UI

If you have used [Floating UI](https://floating-ui.com), the middleware pipeline (`offset`, `flip`, `shift`, `size`, `autoPlacement`) will feel familiar. VFloat shares that same geometric foundation.

The difference is architectural. Floating UI is primarily an imperative vanilla library with framework adapters. VFloat is built natively from the ground up for Vue 3.5 reactivity:

- **Reactivity-first:** Positions and open states are native Vue `Ref`s and computed values. You do not manage manual update loops or animation frame subscriptions.
- **Automatic styling:** `usePosition` applies optimized inline styles directly to the floating element by default, eliminating manual `:style` boilerplate.
- **Tree coordination:** Complex hierarchies like nested submenus or stacked dialogs synchronize automatically through reactive parent-child node trees.
